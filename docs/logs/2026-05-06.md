# 2026-05-06

## Bootstrap

Started the project. Captured ambition and structure in `CLAUDE.md` and
seeded the wiki with `index.md` + `roadmap.md`.

### Decisions

- **Provider addressing as `"provider/model"` strings.** Keeps the core
  free of provider-specific types and lets users wire any backend through
  a single `Provider` interface. Cost: a small registry/dispatch layer
  later. Accepted because the alternative (typed provider configs in the
  core) leaks vendor concepts into the SDK and breaks the "lean" rule.

- **Stdlib-only core until proven otherwise.** Every dependency must earn
  its place with a log entry. Reduces churn from upstream breakage and
  keeps the SDK embeddable in environments with strict supply-chain
  rules.

- **Karpathy-style auto-documentation.** Two folders:
  - `docs/logs/` — append-only, one file per day (`YYYY-MM-DD.md`),
    multiple entries as `##` sections. Past days are not edited;
    corrections go in a new day's entry.
  - `docs/wiki/` — current-state knowledge, rewritten freely.

  Chose one-file-per-day over one-file-per-entry because most days will
  have a few small notes; per-entry files would fragment the history and
  make scanning a day's work harder. The cost is that two parallel
  workstreams on the same day share a file — acceptable while the project
  is small.

- **Roadmap stages are gated.** Stage N+1 only begins once Stage N is
  ship-ready on its own. This is the lever that enforces "composable":
  if a later stage can't be deferred, the earlier stage's interface is
  wrong.

### Open questions

- Exact shape of the `Provider` interface — single-shot vs. streaming as
  the primitive. Will be decided when Stage 1 starts; logging here so we
  remember to revisit.
- Tool schema representation — JSON Schema as `map[string]any`, a typed
  builder, or something reflective. Same: deferred to Stage 1.

### Not done yet

- No Go code. No `go.mod`. Stage 1 will start there.

## Stage 1: LLM interface + three providers

Shipped the bare-bones LLM contract and three stdlib-HTTP provider
implementations: OpenAI, Anthropic, Gemini. One package, no external deps.

### Decisions

- **LLM is just `Complete(ctx, []Message) (string, error)`.** No tools, no
  system prompt, no streaming. The whole conversation goes in on every
  call (LLM is a pure function of context). Statefulness is built above.
  Keeps the interface to one job — the smallest thing that earns the
  name "LLM".

- **`Complete` returns `string`, not `Message`.** The reply is always
  assistant-role, so making the role implicit keeps the asymmetry honest:
  text-with-roles in, plain text out. Will be revisited if/when assistant
  turns carry more than text (tool calls).

- **Model bound at construction, not per-call.** A `*OpenAI{Model: ...}`
  is a handle for one model. The `"provider/model"` string from the
  bootstrap decision is what a future registry will use to *build* the
  handle — not a parameter the interface itself carries.

- **`Role` covers `user` and `assistant` only.** No `system` yet. System
  prompts are configuration-shaped, not turn-shaped. We resist sneaking
  it onto the provider struct until something concrete needs it.

- **Same shape across providers.** Each provider is a struct with
  `APIKey/Model/BaseURL/Client` (Anthropic adds `MaxTokens` because the
  API requires it) plus a `Complete` method. Pattern duplicated, not
  abstracted — three is too few for a base type to earn its keep.

- **`var _ LLM = (*X)(nil)` per provider.** Compile-time interface
  assertion. Cheap insurance against silent contract drift; worth the
  one line.

- **No vendor SDKs.** stdlib `net/http` + `encoding/json` only. Honors
  the bootstrap "stdlib until proven otherwise" rule and means consumers
  pick up zero transitive deps.

- **Anthropic `max_tokens` default is 4096.** The API rejects requests
  without it, so the zero-value `Anthropic{}` would be unusable. We
  default-on-zero rather than require an explicit field, because the
  field is a quirk of one provider and shouldn't bleed into the cross-
  provider mental model.

- **Gemini "assistant" → "model" rename happens inside `Complete`.**
  Callers stay on our `RoleAssistant`; the wire-format quirk is the
  provider's problem. Tested explicitly because it's the kind of one-`if`
  translation that silently breaks.

- **Tests cover provider-specific quirks only.** No tests for "HTTP
  works" or "JSON marshals". The four tests live where bugs realistically
  hide: Gemini role rename, Anthropic mixed-block concatenation,
  Anthropic `MaxTokens` default, OpenAI empty-`choices` error path.

- **Tests use `// given` / `// when` / `// then`.** Explicit phase
  markers. Trades a few comment lines for unambiguous intent — small
  test files, so the noise floor is low.

### Process notes

- Overshot scope on the first attempt at Stage 1 (wrote message + tool +
  provider + agent loop + tests in one batch). User course-corrected:
  build slowly, conscious decisions, smallest interpretable slice. Saved
  as a feedback memory. Re-applying going forward.

- **Module path must match the origin remote.** Initially set to
  `github.com/gdforj/gharness` (matched local user); origin is
  `github.com/GuillaumeDesforges/gharness`. Fixed before first push so
  consumers can `go get` under the canonical path.

- **cgo gotcha on this box.** `go build` defaults to `CGO_ENABLED=1` on
  Linux and pulls in `runtime/cgo` for the libc DNS resolver, which
  needs `gcc`. This box has none. Workaround: `CGO_ENABLED=0` for build
  and test. Not encoded in the project — it's an environment fact;
  consumers/CI choose their own cgo policy.

### Resolved from bootstrap "open questions"

- **Provider primitive: single-shot.** Streaming layered on later if and
  when needed.
- **Tool schema: deferred.** No tools in this stage; the question is
  reopened when tools land.

## Knowledge layer formalized

Adopted the Karpathy LLM Wiki pattern explicitly, adapted for an
engineering project. Re-shaped `CLAUDE.md` and backfilled wiki pages so
the catalog reflects committed code.

### Decisions

- **Three layers, named.** Schema = `CLAUDE.md`. Wiki = `docs/wiki/`
  (current-state synthesis). Raw = `docs/logs/` + git history
  (decisions + diffs, both immutable).

- **Keep one log file per day.** Karpathy's gist proposes a single
  `log.md` with `## [YYYY-MM-DD] type | title` headers. We keep
  per-day files (already established in the bootstrap) because the
  pattern is working and fragmentation is manageable at our scale.

- **No separate `docs/raw/` directory.** The "raw" layer in Karpathy's
  pattern is the immutable source the wiki distills from. For an
  engineering project, our daily decision logs (immutable, append-only)
  plus git diffs (immutable by nature) already serve that role. A
  third directory would just duplicate.

- **Commit workflow: wiki updates land in the same commit as the code
  change that motivates them.** Catches the perpetual-lag failure mode
  before it starts. Encoded in `CLAUDE.md` so future sessions inherit
  it.

- **Operations vocabulary lifted from the gist.** Ingest, query, lint —
  same names, lightly adapted to engineering work. Worth the small
  cognitive cost because it makes the pattern self-documenting:
  "operations" become a known interface rather than ad-hoc habits.

### Backfill

Three new wiki pages created so the catalog reflects what's already
committed (the rule applies retroactively to this initial setup):

- `docs/wiki/llm.md` — the `LLM` contract, types, design choices,
  what's deferred.
- `docs/wiki/providers.md` — shared shape of the three providers,
  per-provider quirks, error format.
- `docs/wiki/testing.md` — scope, `httptest` pattern, given/when/then
  conventions.

`docs/wiki/index.md` rewritten as a categorized catalog (Plan / Design
/ Implementation / Conventions) with conventions for keeping it in sync.

## Wiki scope refined

Course-correction on what the wiki is for: "the wiki should not focus
on implementation, the code is here for that. the wiki should focus on
specification, design decisions, and building knowledge about concepts."

### Decision

- **Wiki documents spec + decisions + concepts; never implementation.**
  The code is the source of truth for *how*; the wiki carries *what is
  required*, *why we chose it*, and *what concepts mean*. Anything the
  code shows directly (wire formats, header names, JSON paths, struct
  field tables, restated signatures) is removed from the wiki, because
  duplication is what makes wikis rot.

### Refactor

The three backfilled pages refocused:

- `llm.md` — kept the contract and design decisions; reframed the
  "Types" listing as "Specification" (the contract, not the type's
  field list).
- `providers.md` — dropped wire-format quirks (auth headers, JSON
  paths, role-rename details) and the field/usage tables. Kept *what
  providers must do* and the design choices (stdlib-only, duplicated-
  not-abstracted, vendor quirks hidden in `Complete`, zero-value
  usability, compile-time interface assertion).
- `testing.md` — removed the `httptest` code snippet that was acting
  as reference. Kept the scope rules and the given/when/then
  discipline.

`index.md` recategorized to Plan / Design / Conventions; the
"Implementation" category retired so it doesn't tempt drift.

`CLAUDE.md` made the wiki's scope explicit so future sessions inherit
the rule.

## Core moved into its own folder; basic example added

Moved the seven `llm*.go` files (interface + three providers + their
tests) from the repo root into `core/` and renamed the package from
`gharness` to `core`. Added `examples/basic/main.go` — a runnable smoke
test that hits the real Anthropic API using `ANTHROPIC_API_KEY` from
the environment.

### Decisions

- **Subpackage named `core`.** Matches the roadmap's "Stage 1 — Core
  domain" framing. Future stages (skills, MCP, memory) will land as
  sibling packages, leaving `core/` untouched and independently usable
  as the roadmap requires.

- **Single Go module, not nested modules.** The example imports
  `github.com/GuillaumeDesforges/gharness/core` directly. A separate
  `examples/` module would only be worth its complexity if examples
  depended on something the core doesn't — they don't.

- **Example demonstrates one provider, not all three.** "Basic" means
  one straight-line path that proves the contract works end-to-end. A
  three-provider matrix is a smoke harness, which is a different
  artefact and not the named scope.

- **Anthropic chosen for the example.** Aligns with the model named in
  the project's ambition (`anthropic/claude-opus-4-7`). No deeper
  reason; the other two providers are equally valid demonstrators.

- **API key from env, not flag.** Standard pattern for credentials,
  keeps the example a single file with no flag-parsing noise.

### Wiki

- `docs/wiki/llm.md`: updated the file path from `llm.go` to
  `core/llm.go`. The contract didn't change; only its location did.
- No new wiki page for the example. Examples are illustrations of the
  contract, not part of it; the wiki is for spec/decisions/concepts,
  not runnable artefacts.

## Tools landed in the LLM contract

Stage 1's tool slice. Designed the erased `Tool` shape, grew `Message`
and `Complete` to carry tool calls and tool results, and plumbed all
three providers end-to-end. No agent loop yet — that's the next slice.

### Decisions

- **`Tool` is a struct with fields, not an interface.** Inline literals
  (`Tool{Name: ..., Execute: ...}`) are dramatically more pleasant than
  receiver-method types when there's nothing polymorphic to express. A
  future generic helper (`NewTool[In, Out]`) returns a `Tool` directly
  with no interface dance. We can lift to an interface later if a
  stateful implementation ever forces it; for now, three-is-too-few
  applies, same as the providers.

- **Description required.** Every provider asks for it; `""` is a free
  escape hatch if the author truly has nothing to say. Required
  defaults reduce missing-field bugs at construction.

- **Schema as `map[string]any`.** Stdlib-only, wire-shaped, matches
  what every provider sends and what a reflective wrapper would
  produce. `json.RawMessage` would force providers to unmarshal before
  rewriting per-vendor schema dialects (Gemini's differs subtly from
  strict JSON Schema). A typed schema library would break the
  stdlib-only rule.

- **Tool input as `json.RawMessage`, output as `string`.** Inputs name
  the contract ("these are JSON bytes") without re-encoding and let a
  generic wrapper unmarshal once into `In`. Outputs travel back to the
  model as text, so `string` is the boundary shape; JSON-shaped
  outputs serialize themselves on the way out. The reverse — bytes out
  — would force every text tool to wrap itself.

- **Grew `Message` instead of switching to a block-list or sealed
  variant.** Added `ToolCalls []ToolCall` and `ToolCallID string` plus
  a new `RoleTool`. Invariants ("`ToolCallID` only meaningful when
  `Role == RoleTool`") are unenforced — that's the cost. The win is no
  sealed-interface gymnastics, no per-block marshal/unmarshal
  machinery, and a clean append-to-history flow. A block-list would
  match Anthropic's wire shape losslessly but is substantially more
  code for a payoff (interleaved text + tool calls) we don't need.

- **Reply is `Message`, not `string` or `(string, []ToolCall)`.**
  Reverses the original "text in roles, plain text out" choice — that
  asymmetry was honest only while assistant turns were plain text.
  Symmetric input/output and one-step `append(history, reply)` outweigh
  the redundant `Role: RoleAssistant` on output.

- **`tools` is a per-call argument.** Stage 2 (skills) will attach and
  detach tools per agent turn; binding them at provider construction
  would force Stage 2 to reshape `Complete`. Per-call now means no
  migration later.

- **Call IDs are gharness-internal.** The agent uses them to match a
  result back to the call that produced it. The provider hides the
  vendor side: when the vendor doesn't carry IDs natively, the
  provider synthesizes them.

### Vendor quirks absorbed

Each provider hides one or more vendor-specific oddities:

- **Anthropic.** Always sends messages as block-lists (simpler than
  branching on string-vs-blocks). When N tool_use blocks come back,
  the API requires the next user turn to bundle N tool_result blocks
  in a single message; consecutive `RoleTool` messages are merged
  internally.

- **OpenAI.** Function arguments travel as a JSON-encoded *string* on
  the wire, not a JSON object. The provider stringifies on the way out
  and re-wraps incoming `arguments` strings as `json.RawMessage` for
  the contract.

- **Gemini.** Function calls don't carry IDs on the wire and matching
  is by function name. The provider synthesizes IDs (`name-index`) on
  decode and looks the name back up by walking prior assistant turns
  when encoding tool results into `functionResponse` parts. Tool
  results are nested inside a user content with `{content: ...}` as
  the response object.

### Tests

Followed the established convention (provider-specific quirks only;
no "HTTP works", no "JSON marshals"). Existing tests updated for the
new return type. Added one quirk test per provider:

- Anthropic: consecutive tool results merge into one user message.
- OpenAI: `tool_calls.function.arguments` is a JSON string on the
  wire; decode round-trips a tool call back into a `ToolCall`.
- Gemini: tool results translate to `functionResponse` parts with
  the looked-up name; decoded calls get synthesized IDs.

### Deferred (still)

- **Agent loop.** User-scoped out for this slice. Next.
- **Generic tool helper** (`NewTool[In, Out any]`). The erased shape
  was designed to wrap cleanly, but reflective schema generation is
  non-trivial and we have no concrete pain yet.

## Agent: interface + FixedPointAgent

Stage 1's last slice. Designed an `Agent` interface and a
`FixedPointAgent` struct that loops `Complete`-and-execute until the
assistant returns a turn with no tool calls. Six tests against a
scripted fake LLM cover the loop's documented behaviors.

### Decisions

- **`Agent` is an interface, not a struct.** Diverges from the
  three-is-too-few rule that left `Tool` and the providers concrete.
  Justified because the agent is the top of the stack: wrapping it
  (tracing, budget caps, alternate orchestrations later) is a natural
  use case, and the interface gives users a seam they can replace
  without forking the loop. Same compile-time `var _ Agent` assertion
  the providers carry.

- **Single method `Run(ctx, history) ([]Message, error)`.** No `Step`
  for one-tick iteration. Speculative surface until a UI or test forces
  it; consumers wanting external control can wrap the interface.

- **Fixed-point stop rule.** The assistant's empty `ToolCalls` is the
  signal. Any other stop policy (turn count match, sentinel tool) lives
  above the core.

- **`MaxSteps` zero means infinite.** Considered "required positive,
  zero invalid" and "zero means a built-in default of N" — both
  rejected. The first is ceremony for callers who don't have a budget
  problem yet; the second is silently magical. Zero-as-infinite is
  honest: you didn't ask for a cap, so there isn't one. No sentinel
  error on cap; the caller detects exhaustion by inspecting the last
  message's `ToolCalls`.

- **Tool failures become `RoleTool` messages.** Both `Tool.Execute`
  errors and unknown-tool calls are caught and turned into tool-result
  messages whose content is an error string, so the model can
  self-correct in the same run. Bubbling them as Go errors would force
  every caller to invent a recovery loop the agent already has.
  Single error policy across both failure modes — no special case for
  unknown tools.

- **Partial history on error.** When `Run` returns a non-nil error
  (currently only `Complete` failures), the accumulated history is
  returned alongside. The transcript at the moment of failure is the
  most useful diagnostic the caller has, and costs nothing.

- **Agent owns no conversation state.** History is passed in and
  returned. Mirrors the LLM contract's pure-function-of-context shape.
  Skills (Stage 2) will configure tool/prompt sets on the agent, not
  conversation state.

### Tests

Same convention as the rest of the package: provider/loop quirks only,
no stdlib re-testing.

- Stops when the first assistant turn has no tool calls.
- Loops once: tool gets executed, result lands in history with the
  right `ToolCallID`, second LLM call sees the appended history and
  returns the final text.
- `Tool.Execute` returning an error becomes a `RoleTool` whose content
  is `err.Error()`.
- Calling an unknown tool name becomes a `RoleTool` mentioning the
  name.
- `MaxSteps=2` halts the loop after exactly two LLM calls when the
  assistant keeps requesting tools.
- A failing `LLM.Complete` returns the input history unchanged
  alongside the error.

### Deferred

- Streaming, step events / observability hooks, parallel tool dispatch.
- Sentinel error or structured stop reason on cap exhaustion (callers
  inspect the last message instead).
- System prompt field on `FixedPointAgent` — stays deferred to Stage 2
  the same way it's deferred at the LLM layer.

### Stage 1 done

Roadmap's done-when condition for Stage 1 is now satisfied: the core
can be embedded, given a fake provider and tools, and runs a turn-based
loop end-to-end under test. Stage 2 (skills) is the next thing that
gets touched.

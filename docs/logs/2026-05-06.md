# 2026-05-06

## Bootstrap

Started the project. Captured ambition and structure in `CLAUDE.md` and
seeded the wiki with `index.md` + `roadmap.md`.

### Decisions

- **Provider addressing as `"provider/model"` strings.** Keeps the core
  free of provider-specific types and lets users wire any backend through
  a single `Provider` interface. Cost: a small registry/dispatch layer
  later. Accepted because the alternative (typed provider configs in the
  core) leaks vendor concepts into the SDK and breaks the "lean" rule.

- **Stdlib-only core until proven otherwise.** Every dependency must earn
  its place with a log entry. Reduces churn from upstream breakage and
  keeps the SDK embeddable in environments with strict supply-chain
  rules.

- **Karpathy-style auto-documentation.** Two folders:
  - `docs/logs/` — append-only, one file per day (`YYYY-MM-DD.md`),
    multiple entries as `##` sections. Past days are not edited;
    corrections go in a new day's entry.
  - `docs/wiki/` — current-state knowledge, rewritten freely.

  Chose one-file-per-day over one-file-per-entry because most days will
  have a few small notes; per-entry files would fragment the history and
  make scanning a day's work harder. The cost is that two parallel
  workstreams on the same day share a file — acceptable while the project
  is small.

- **Roadmap stages are gated.** Stage N+1 only begins once Stage N is
  ship-ready on its own. This is the lever that enforces "composable":
  if a later stage can't be deferred, the earlier stage's interface is
  wrong.

### Open questions

- Exact shape of the `Provider` interface — single-shot vs. streaming as
  the primitive. Will be decided when Stage 1 starts; logging here so we
  remember to revisit.
- Tool schema representation — JSON Schema as `map[string]any`, a typed
  builder, or something reflective. Same: deferred to Stage 1.

### Not done yet

- No Go code. No `go.mod`. Stage 1 will start there.

## Stage 1: LLM interface + three providers

Shipped the bare-bones LLM contract and three stdlib-HTTP provider
implementations: OpenAI, Anthropic, Gemini. One package, no external deps.

### Decisions

- **LLM is just `Complete(ctx, []Message) (string, error)`.** No tools, no
  system prompt, no streaming. The whole conversation goes in on every
  call (LLM is a pure function of context). Statefulness is built above.
  Keeps the interface to one job — the smallest thing that earns the
  name "LLM".

- **`Complete` returns `string`, not `Message`.** The reply is always
  assistant-role, so making the role implicit keeps the asymmetry honest:
  text-with-roles in, plain text out. Will be revisited if/when assistant
  turns carry more than text (tool calls).

- **Model bound at construction, not per-call.** A `*OpenAI{Model: ...}`
  is a handle for one model. The `"provider/model"` string from the
  bootstrap decision is what a future registry will use to *build* the
  handle — not a parameter the interface itself carries.

- **`Role` covers `user` and `assistant` only.** No `system` yet. System
  prompts are configuration-shaped, not turn-shaped. We resist sneaking
  it onto the provider struct until something concrete needs it.

- **Same shape across providers.** Each provider is a struct with
  `APIKey/Model/BaseURL/Client` (Anthropic adds `MaxTokens` because the
  API requires it) plus a `Complete` method. Pattern duplicated, not
  abstracted — three is too few for a base type to earn its keep.

- **`var _ LLM = (*X)(nil)` per provider.** Compile-time interface
  assertion. Cheap insurance against silent contract drift; worth the
  one line.

- **No vendor SDKs.** stdlib `net/http` + `encoding/json` only. Honors
  the bootstrap "stdlib until proven otherwise" rule and means consumers
  pick up zero transitive deps.

- **Anthropic `max_tokens` default is 4096.** The API rejects requests
  without it, so the zero-value `Anthropic{}` would be unusable. We
  default-on-zero rather than require an explicit field, because the
  field is a quirk of one provider and shouldn't bleed into the cross-
  provider mental model.

- **Gemini "assistant" → "model" rename happens inside `Complete`.**
  Callers stay on our `RoleAssistant`; the wire-format quirk is the
  provider's problem. Tested explicitly because it's the kind of one-`if`
  translation that silently breaks.

- **Tests cover provider-specific quirks only.** No tests for "HTTP
  works" or "JSON marshals". The four tests live where bugs realistically
  hide: Gemini role rename, Anthropic mixed-block concatenation,
  Anthropic `MaxTokens` default, OpenAI empty-`choices` error path.

- **Tests use `// given` / `// when` / `// then`.** Explicit phase
  markers. Trades a few comment lines for unambiguous intent — small
  test files, so the noise floor is low.

### Process notes

- Overshot scope on the first attempt at Stage 1 (wrote message + tool +
  provider + agent loop + tests in one batch). User course-corrected:
  build slowly, conscious decisions, smallest interpretable slice. Saved
  as a feedback memory. Re-applying going forward.

- **Module path must match the origin remote.** Initially set to
  `github.com/gdforj/gharness` (matched local user); origin is
  `github.com/GuillaumeDesforges/gharness`. Fixed before first push so
  consumers can `go get` under the canonical path.

- **cgo gotcha on this box.** `go build` defaults to `CGO_ENABLED=1` on
  Linux and pulls in `runtime/cgo` for the libc DNS resolver, which
  needs `gcc`. This box has none. Workaround: `CGO_ENABLED=0` for build
  and test. Not encoded in the project — it's an environment fact;
  consumers/CI choose their own cgo policy.

### Resolved from bootstrap "open questions"

- **Provider primitive: single-shot.** Streaming layered on later if and
  when needed.
- **Tool schema: deferred.** No tools in this stage; the question is
  reopened when tools land.
